# RA i18n — language selector (en · pt-BR · ja · de · pl)

RA ships a five-locale language system covering the TUI chrome and the agent's
**output** language. One `ra/src/i18n.ts`, no dependencies (Intl is stdlib).

## How it works

**Locale resolution order** (first match wins):

1. `~/.ra/locale.json` — the persisted lock (`{ "locale": "ja" }`, same shape
   and directory as the `tui.json` prefs)
2. `LC_ALL` / `LANG` environment variables (checked in that order)
3. `Intl.DateTimeFormat().resolvedOptions().locale` (the OS/terminal locale)

Anything unrecognized — `C`, `xx_YY`, garbage — resolves to `en`.
All `pt*` variants (pt, pt-BR, pt-PT…) map to `pt-BR`.

**Auto-lock on first TUI run**: when no lock exists, `ra` detects the locale
and writes it to `~/.ra/locale.json` immediately. The choice (including the
agent output language) is then stable across sessions and immune to env
changes. Delete the file to re-detect on the next start.

**Translation lookup**: the English string is the catalog key; `t(key, ...args)`
returns the current-locale entry or falls back to the key itself (en). A
missing translation can never crash or blank the UI. `{0}`, `{1}`…
placeholders are interpolated positionally.

**Agent output language**: when the locked locale ≠ `en`, a directive
(`Always respond in Japanese (ja)…`) is injected into the system prompt at
assembly time — both the coding loop (`agent.ts`) and the assistant lane
(`lane.ts`). **Input handling is untouched**: prompts written in any language
keep working exactly as before; routing heuristics stay English-verb based
(see the `ponytail:` note in `lane.ts`).

## Usage

```console
$ ra lang                 # show current + supported languages
RA language: en
supported: en (English) · pt-BR (Português (Brasil)) · ja (日本語) · de (Deutsch) · pl (Polski)
usage: ra lang <code> — locks the UI + agent reply language (~/.ra/locale.json)

$ ra lang ja              # set + lock
RA language → ja (日本語), locked. /lang or ra lang to change it later.

$ ra lang klingon         # unsupported → error, exit 1
```

In the TUI: `/lang` shows the same summary; `/lang de` sets + locks. The
`/lang [code]` entry also appears in the `/` palette and the help text.

The agent directive takes effect on the **next turn** after a switch (the
current in-flight prompt was already assembled).

## Adding a language

1. **Catalog**: add a `Record<string, string>` block for the new code in
   `CATALOGS` (`ra/src/i18n.ts`) with a translation for **every existing key**.
   Keep `{n}` placeholders intact; keep technical terms natural — `checkpoint`,
   `session`, model ids, `/quick`-style command names stay as-is.
2. **Registration**: add the code + display name to `SUPPORTED` and an English
   name to `DIRECTIVE_NAMES` (models parse English names most reliably).
3. **Normalization** (if the code has variants, like `pt` → `pt-BR`): extend
   `normalizeLocale`.
4. **Tests**: `ra/tests/i18n.test.ts` — extend the `SUPPORTED` assertion; the
   completeness sweep, placeholder check, and directive test pick up the new
   locale automatically.

```bash
cd ra && bun test tests/i18n.test.ts   # the sweep enforces the new locale
```

## Testing

`ra/tests/i18n.test.ts` covers: catalog completeness (cross-locale sweep —
every key in every locale), placeholder parity, non-identity translations,
`t()` fallback + interpolation, the detection matrix (env/Intl/garbage),
lock persistence (tmp homes, corrupted files, unwritable homes), the agent
directive (present for ja/de/pl/pt-BR, absent for en), and locale-independent
input routing. Registered in `scripts/verify-release.sh`.

## Known ceilings (ponytail)

- **Natural keys**: rewording an English string orphans its translations until
  the completeness sweep fails — the sweep is the drift guard.
- **No ICU/plural rules**: `{n} file(s)`-style pluralization is not
  inflected; strings are written to read fine with counts inline.
- **No number/date/currency localization**: costs, token counts, and dates
  stay in the existing formats.
- **Routing is English-verb based**: non-English *edit-intent* prompts rely on
  file-target cues (a ja prompt naming `src/app.ts` routes to coding);
  the documented upgrade path is a small model-assisted classifier.
- **Module-load-time capture**: pure renderers (explorer tabs, shortcuts
  table, tips) resolve `t()` once at import; a mid-process `/lang` switch
  fully applies on the next launch (prompts and most chrome switch live).
